# 根因分析与实测结论

本文档记录项目演进中通过物理仿真逐项排查得到的结论，按重要性排列。

## 1. 物体轴向（`p24grasp/kinematics/ik.py` 的 AXIS）

手指在**世界 x–z 平面内**屈曲：任一手指的屈曲关节转 90°，指尖位移约
$(+0.114,\ 0,\ -0.111)$。像握把手一样抓住圆柱，要求圆柱轴**垂直于**该平面。
轴沿 +x 时圆柱正好躺在屈曲平面里，只会被推开；实测横向（+y）与竖直（+z）
都能稳住，+x 在任何姿态下都抓不住。原代码库的 `AXIS = +x` 约定从未被验证过。

同时早期 `build_interactive_scene` 曾同时给物体 body 和 geom 加 90° 四元数，
两次旋转叠加使轴向出错——现在只由 body 四元数定义轴向，geom 保持恒等。

## 2. 指节碰撞体（`p24grasp/model/mjcf.py`）

URDF 里**没有任何 `<collision>` 元素**，生成器直接拿视觉网格当碰撞体，而
MuJoCo 用凸包——指节是弯的（77×24×38 mm），任何抓取姿态下物体都嵌进凸包
20–40 mm，首次接触解算就被轰飞。修复：

- 从 URDF 关节偏移取骨轴，网格顶点投影到该轴；
- 胶囊轴线平移到网格质心相对骨轴的偏移处（肉长在骨头的哪一侧，胶囊就放哪）；
- 半径取垂直散布的 **p75**（上限 p50+5 mm，防拇指基座蹼部异常值）——
  结果 11.8–15.8 mm，贴合视觉指腹；
- 视觉网格纯渲染（黑色 `rgba 0.12 0.12 0.13`），胶囊体透明（纯碰撞）。

实测握持穿透：释放瞬间 −34 mm（物体在手指笼内，0.1 s 内衰减），稳态
**−2.3 ~ −4.3 mm**（DIP 胶囊/指尖球处的软接触压入，正常范围）。

## 3. 接触位掩码（`p24grasp/sim/scene.py`）

MuJoCo 规则：一对几何碰撞当且仅当
$(\mathrm{contype}_1 \ \&\ \mathrm{conaffinity}_2)$ 或
$(\mathrm{conaffinity}_1 \ \&\ \mathrm{contype}_2)$ 非零。当前方案：

| 几何 | contype/conaffinity | 碰撞对象 |
| --- | --- | --- |
| 物体 | 3（bit1+2） | 掌心、手指 |
| 掌心 | 1（bit1） | 仅物体 |
| 指节胶囊 + 指尖球 | 2（bit2） | 物体 + 其他手指 |

早期版本把所有手部几何统一掩码、**手–手碰撞全关**（为了避开掌心凸包吞手指），
因此手指之间没有碰撞；现在手指间碰撞已开启（空手闭合 29 个指间接触、抓握时
10 个），掌心–手指保持排除。

## 4. IK 目标半径的符号（`tip_center_radius`）

`solve_angles` 放置的是 tip link 的坐标系原点，也就是贴在指尖的 8 mm 接触球
的球心。球刚好接触表面时球心应在表面**外**一个球半径处：$r + r_\mathrm{tip}$。
写成 $r - r_\mathrm{tip}$ 会把每个指尖埋进物体 16 mm——这个符号 bug 曾污染了
多轮抓取失败的诊断。

## 5. 观测/动作的关节顺序（`p24grasp/env/obs.py`）

`HandModel.active_joint_names` 按手指链排列（index, little, middle, ring,
thumb），而 hand.xml 的执行器是 thumb 开头。动作向量直接写进 `data.ctrl`，
两者必须一致，否则每条指令都落到错误的关节上。

## 6. mimic 关节 equality（`p24grasp/model/mjcf.py`）

MuJoCo 的 `<joint>` equality 约束的是

$$
q_1 = p_0 + p_1 q_2 + p_2 q_2^2 + \dots
$$

即 joint1 表示为 joint2 的多项式，与 $c_0 + c_1 q_1 + c_2 q_2$ 的直觉写法
相反。旧的 `"offset multiplier -1 0 0"` 实际产生 $q_1 - q_2 + q_2^2 = 0$——
不稳定、分支会跳变的二次约束，DIP 关节等于没有约束，空载下自己漂到限位
（15–21°）。正确写法 `"-offset/m  1/m  0 0 0"`，修改后偏差 0.01° 量级。

## 7. 几何 IK 只能做"开口式包裹"

`solve_angles` 沿**张开姿态**的径向方向定位指尖。这只手真正能包围物体的位置
是**拳心**（`fist_center`，五指全屈曲指尖质心，z≈0.074），而 IK 把物体放在
手指*指向*的 z≈0.16——物体初始就在指节里。RL 环境因此以全屈曲为参考姿态、
物体投放在拳心。初始闭合度必须**拇指与四指分开缩放**（拇指在拳心内侧，统一
缩放会把它顶进物体）。

## 8. PyRoki 可行性

[PyRoki](https://github.com/chungmin99/pyroki)（UC Berkeley，IROS 2025，JAX
可微运动学工具包）已安装实测：

| 能力 | 结论 |
| --- | --- |
| 可微 FK（URDF） | 五指与 HandModel 差 **0.000 mm**（含 mimic 全屈曲） |
| LM IK | 支持 mimic、碰撞代价；比 scipy 版更强 |
| 自动碰撞胶囊体 | 对 URDF 生成 0 个（无 `<collision>` 元素，与 MuJoCo 侧同源问题） |
| 物理仿真 | 无动力学/接触解算/渲染——**替代不了 MuJoCo** |

结论：PyRoki 可替换运动学层，动力学继续由 MuJoCo 承担
（`p24grasp/pyroki/ik.py` 的 IK 目标与碰撞障碍物共享同一 tilt 轴参数）。

## 9. 偶发的 MuJoCo 求解器崩溃

一次实测中 `sim_web.py` 运行 32 s 后段错误，崩溃栈全在 libmujoco 内部
（`mj_step → mj_fwdConstraint → mju_mulMatVec`，空指针）。四轮复现（无浏览器
长跑、假 websocket 客户端、2 万步交替改尺寸、NaN 注入）均未复现；触发窗口是
"物体掉落后自由落体"。已加掉落自动回收（0.5 m 重摆）与 `faulthandler`
（每 90 s 转储线程栈），之后未再出现。若复发，建议升级 MuJoCo。

## 10. "抓住后逐步被挤掉"的机理与对策

**现象**：物体被抓住后漂移缓慢增长（$\sim$1.2 mm/s），$\sim$14 s 后滑出指尖掉落。

**机理**（实测逐项排除）：

1. **指尖物理上包不过物体顶部**。手指完全屈曲时指尖最远到 x≈0.026，而 r=32 mm
   圆柱的远侧表面在 x≈0.056——指尖差 30 mm。抓取实际是"托举"不是"包裹"。
2. **握力方向与逃逸方向一致**。手指闭合的扫动方向是 +x/−z，物体正是沿 +x
   滑脱——手指越用力越把它往前推（湿肥皂效应）。逃逸轨迹实测：位置 x
   从 +2.7→+52.6 mm，角速度仅 $\sim 1$°/s（是滑动不是滚动）。
3. **掌心凸包没有"碗"**。物体浮在掌心凸包顶面（z≈0.073 > 掌心顶缘 0.070），
   +x 方向没有任何接触能提供反力。

**排除的控制干预**（全部 $\sim$14 s 失败）：kp 0.5/2/5（13.8/12.1/15.8 s）、
提前预紧、松-紧重新抓握、滚动摩擦 0.02→0.7、钩形握法、掌心加唇、手后仰
15–35°、加深/降低摆放位置。

**有效对策**：

1. **包裹对齐摆放**（`wrap_aligned_center`）：把圆柱远侧表面对齐指尖最远
   可达点（中心 $x = 0.026 - r$）。r=26 mm 时 5/5 试验保持 30 s、60 s 测试
   保持到 $\sim$35-40 s——比默认拳心位置（14 s）提高约 3 倍。r=32 mm 在该位置
   初始即穿透（指尖确实够不到）。
2. **自动重抓**（`DROP_RESPAWN=0.12 m`）：滑脱前自动重摆，交互上无缝。
3. 默认半径从 32 mm 改为 **26 mm**（这只手能包裹的最大圆柱）。

**根本限制**：这只手的指尖可达半径约 26 mm；更大的物体只能托举，任何
控制策略都无法把托举变成包裹（除非改模型几何或加指尖软垫）。

## 环境基线（确定性 episode）

| 行为 | 结果 |
| --- | --- |
| 固定标称握姿（拇指 0.6 / 四指 0.9 × 全屈曲） | 全程 4 s 保持，回报 +438.6，漂移 55 mm |
| 不做任何动作 | 0.61 s 掉落，回报 +19.4 |
| 几何 IK 摆位 + IK 目标角 | 0.3 s 内飞出 |

即：**关节角度能跟到几何 IK 的期望值（误差 ~1°），但那套"期望角度"本身
不构成抓取（成功率 0%）；RL 找到的握姿能真正把物体保持在手里。**
